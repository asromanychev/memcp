# Настройка MCP через TCP

Инструкция по настройке MCP сервера для работы через TCP вместо STDIO.

## Архитектура

```
[Корпоративный ноутбук]              [Серверный ноутбук]
├── Cursor IDE                       ├── Rails API (3001)
├── mcp_tcp_client.rb (STDIO)  ────→ ├── mcp_tcp_server.rb (TCP 3002)
└── STDIO ↔ TCP прокси               └── TCP ↔ HTTP прокси
```

## Настройка на серверном ноутбуке

### 1. Запустить TCP MCP сервер

```bash
cd /home/aromanychev/dev/mcp/memcp
MEMCP_API_URL=http://localhost:3001 ruby mcp_tcp_server.rb
```

Или с указанием порта:

```bash
MCP_TCP_PORT=3002 MEMCP_API_URL=http://localhost:3001 ruby mcp_tcp_server.rb
```

Сервер будет слушать на `0.0.0.0:3002` (доступен из сети).

### 2. Проверить работу TCP сервера

```bash
# С серверного ноутбука
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | nc localhost 3002

# Должен вернуть JSON с информацией о сервере
```

### 3. Настроить firewall (если нужно)

```bash
sudo ufw allow 3002/tcp  # Linux
```

## Настройка на корпоративном ноутбуке

### 1. Скопировать mcp_tcp_client.rb

Скопируйте файл `mcp_tcp_client.rb` с серверного ноутбука на корпоративный ноутбук.

### 2. Настроить Cursor IDE

Создайте или отредактируйте `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "memcp": {
      "command": "ruby",
      "args": [
        "/path/to/mcp_tcp_client.rb",
        "192.168.0.93",
        "3002"
      ],
      "env": {
        "MCP_TCP_HOST": "192.168.0.93",
        "MCP_TCP_PORT": "3002"
      }
    }
  }
}
```

**Важно:**
- Замените `/path/to/mcp_tcp_client.rb` на реальный путь к файлу на корпоративном ноутбуке
- Замените `192.168.0.93` на IP адрес серверного ноутбука
- Порт `3002` - это порт TCP MCP сервера (не путать с Rails API на 3001)

### 3. Перезапустить Cursor IDE

Полностью закройте и перезапустите Cursor IDE.

## Проверка работы

### На серверном ноутбуке

```bash
# Проверить, что TCP сервер слушает
ss -tulpn | grep :3002
# Должно показать: 0.0.0.0:3002

# Проверить логи TCP сервера (выводятся в консоль)
```

### На корпоративном ноутбуке

1. Откройте Cursor IDE
2. Попробуйте использовать инструменты `recall` и `save`
3. Проверьте логи Cursor IDE (Developer Tools → Console)

## Преимущества TCP подхода

1. **Централизованный сервер** - один TCP сервер на серверном ноутбуке
2. **Несколько клиентов** - можно подключить несколько Cursor IDE одновременно
3. **Проще отладка** - можно тестировать TCP сервер напрямую через `nc` или `telnet`
4. **Меньше зависимостей** - клиенту не нужен доступ к Rails API напрямую

## Недостатки

1. **Дополнительный компонент** - нужно запускать TCP сервер отдельно
2. **Нестандартно** - стандартный MCP работает через STDIO
3. **Сетевая зависимость** - требуется стабильное сетевое подключение

## Troubleshooting

### Проблема: "Cannot connect to MCP TCP server"

**Решение:**
1. Проверьте, что TCP сервер запущен на серверном ноутбуке
2. Проверьте IP адрес и порт в конфигурации
3. Проверьте firewall на серверном ноутбуке
4. Проверьте сетевую доступность: `ping 192.168.0.93`

### Проблема: "Connection refused"

**Решение:**
```bash
# На серверном ноутбуке
ss -tulpn | grep :3002
# Если порт не слушается, запустите TCP сервер
```

### Проблема: TCP сервер не отвечает

**Решение:**
1. Проверьте, что Rails API запущен: `curl http://localhost:3001/up`
2. Проверьте переменную окружения `MEMCP_API_URL` при запуске TCP сервера
3. Проверьте логи TCP сервера (выводятся в консоль)

## Альтернатива: STDIO подход (рекомендуется)

Если TCP не нужен, можно использовать стандартный STDIO подход:
- `mcp_server.rb` работает через STDIO
- Каждый клиент запускает свой процесс
- Проще настройка, стандартный протокол

См. `REMOTE_SETUP.md` для настройки STDIO подхода.
